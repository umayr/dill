# Alpha file-secret contract (implementation under qualification)

The approved private preview-confirmation extension is specified in [alpha-secrets-preview-proof.md](alpha-secrets-preview-proof.md); it is implemented, with Linux and paired runtime qualification pending.

The Stage A preflight and Stage B CLI/adapter implementation, including narrower runtime prerequisites (Linux >=6.5 exact peer pidfds and a dedicated qualified Podman service), are documented in [alpha-secrets-preflight.md](alpha-secrets-preflight.md). Core delivery is wired; preview proofs are implemented; real Linux and paired runtime qualification remain pending. This is not release qualification.

This is a bounded implementation contract for the single-host Alpha, not completion of [#10](https://github.com/umayr/dill/issues/10), [#16](https://github.com/umayr/dill/issues/16), [#19](https://github.com/umayr/dill/issues/19), [#38](https://github.com/umayr/dill/issues/38), or [Brine #8](https://github.com/umayr/brine/issues/8). It requires paired implementation and review. The existing `dill protocol` advertises only `protocol.check`; its metadata codec does **not** execute deployments, discover targets or resolve secrets. This contract does not extend that protocol or require a new IR/RPC system.

## CLI authority and safe diagnostics

`--secret-bindings ABS` selects a deployment document; `--secret-target ID` is
supplied independently by the trusted launcher/operator. The binding may never
select policy authority. `DILL_SECRET_POLICY` is captured from the trusted process
environment before loading recipe environment files; no target environment
variable or recipe field selects the target. Global and command forms share the
same options. Brine always supplies explicit matching `-p`, engine and socket.
Standalone Dill may omit `-p` only with an explicit nonempty `config.name` that
matches the trusted binding/policy stack. With strict target/policy selectors, a
nonempty evaluated name may not override or disagree with explicit `-p`, even for
an ordinary binding-free config; an empty ordinary name may use trusted `-p`.
Legacy no-selector ordinary name overrides remain unchanged.

The presence (even empty) of binding, target, proof selectors, trusted policy
setting, or `secrets check` enables fixed errors and suppresses parser, Pkl, SDK
and debug diagnostics before evaluation. Known-private Pkl evaluation has a
10-second deadline, stdout bound of 8 MiB and stderr bound of 64 KiB. This is not
Pkl sandboxing. Successful decoding that reveals grants enables the same safe
diagnostics thereafter. Without selectors, an evaluation failure retains legacy
Pkl diagnostics; no text scanning/classifier is introduced. A target/policy hint
alone is **not** secret classification: ordinary evaluated configs without grants
or explicit binding/proof requests keep ordinary semantics, without bindings or
source checks. Evaluated/imported grants without bindings fail before engine
access. Cleanup is exempt from availability checks, not from ownership checks.

## Trust and scope

One trusted operator administers a Linux host, local engine, policy, source provisioning, Brine and deployed recipes. Both Docker and Podman use externally provisioned protected **versioned regular host files** on the local daemon host. Native Podman secrets are deferred. Delivery is file-only, read-only to the workload, explicitly granted per service. No Swarm, vault, provider plugins, secret environment delivery, value upload, source deletion, or automatic rotation. Dill never reads source bytes. Registry/Git credentials and control-plane authentication are separate.

This is not a multi-tenant sandbox. Pkl can read inputs allowed to its process and produce arbitrary strings; ordinary environment, command, labels and workload logs can contain sensitive data. Existing `config`, Pkl diagnostics, heuristic plan redaction and environment hashing are not taint-safe. An authorized workload can copy or log a granted secret; an operator with engine access can inspect mounts or read secrets. Do not claim arbitrary artifacts, logs, Pkl evaluation, or unrelated legacy fields are secret-free. Use trusted Pkl and non-secret environment inputs; do not put credentials in Pkl, legacy `--env-file`, or Brine's server environment. Secret reference fields and their errors must never include values or value-derived hashes.

## Additive authoring and binding

Add to current `dill.pkl` and JSON/Go types, not the experimental #38 fixtures:

```pkl
class SecretRequirement { name: String }
class SecretGrant {
  name: String                 // declared logical requirement
  target: String               // absolute container file path
  uid: Int = 0                 // container numeric IDs, not names
  gid: Int = 0
  mode: Int = 256              // decimal 0400
}
// DillConfig: secrets: Listing<SecretRequirement> = new {}
// Service: secrets: Listing<SecretGrant> = new {}
```

Names match `^[a-z][a-z0-9-]{0,62}$`; unique declarations and unique grant names and targets per service; every grant resolves to a declaration. A declaration without a grant is allowed, but a binding is required for every granted name. Validate after Pkl evaluation and again for any Go entrypoint; do not silently drop unknown JSON properties. `target` is a clean absolute Linux path under `/run/secrets/`, with no empty, `.` or `..` components; reject overlap with another secret target or any ordinary mount target (including ancestor/descendant), and reject duplicate bindings. IDs are integers 0..2147483647; mode is exactly decimal 256 (0400) or 288 (0440). No executable, group-write or world access. These restrictions are intentionally narrow. Defaults preserve old configurations; unsupported declarations must fail on an old binary rather than be silently ignored.

Bindings are a separate, operator-selected deployment JSON file, not injected into Pkl and not executable Pkl. Example:

```json
{"version":"dill.secret-bindings/1","target":"lab-a","stack":"demo","bindings":[{"name":"db-password","source":"db-prod","revision":"r2"}]}
```

Exact keys, non-null values, no duplicates/unknowns, bounded input (64 KiB, 256 entries, 128-byte strings), UTF-8, one JSON object and EOF. `target`, `stack`, `name`, `source`, `revision` match the name grammar above. Require explicit nonempty `config.name`, exact trusted binding/policy stack identity, explicit `--engine`, canonical absolute `--engine-socket` (or its existing `unix:///` spelling) and operator-selected `--secret-target <id>`; if `-p` is supplied it must equal `config.name`. No path-derived name or binding-selected target for secret-enabled deployments. Brine always supplies trusted `-p`; standalone Dill does not require it. The file target and stack must equal the resolved trusted target and stack. Bindings may contain only declared names, at most one each; unused declared bindings may exist but do not grant access. References are metadata, not secret bytes; use opaque non-sensitive identifiers, never passwords as names or revisions. Brine stores only this document per deployment, not source paths. Changing the reference is an explicit reviewed config change.

Trusted policy is provisioned independently outside the checkout/Brine workspace, selected by operator-controlled `DILL_SECRET_POLICY` (absolute path), not by Pkl or a deployment binding. Strict JSON, same parser limits, owned and writable only by the operator, with protected parent directories. Example, one entry per authorized source revision:

```json
{"version":"dill.secret-policy/1","targets":[{"id":"lab-a","engine":"docker","socket":"/run/docker.sock","stacks":[{"name":"demo","sources":[{"id":"db-prod","revision":"r2","kind":"hostFile","path":"/srv/dill-secrets/demo/db-r2","uid":1000,"gid":1000,"mode":256}]}]}]}
```

Both engines use exactly the illustrated `hostFile` fields; no other kind or fields are accepted; target IDs, stack names, and source/revision pairs are unique in their respective scopes. Paths are trusted operator metadata, not submitted by Brine. Only exact `(target, stack, source, revision)` entries authorize resolution; Pkl and binding files cannot expand the allowlist. Policy revisions are append-only while referenced: never remap an existing tuple; use a new revision and new immutable source. This is an operator obligation, not something Dill can establish historically. A source can intentionally be authorized to multiple stacks only by explicit entries. For each selected service, all grants must resolve to host files before any mutation.

## Target, preflight and runtime

Secret-enabled operations require explicit local `--engine-socket` matching the policy's canonical absolute Unix socket path and engine, and Linux. Reject remote, implicit endpoint, Docker Desktop/VM filesystem indirection, and unsupported modes; the operator must ensure the socket really serves the local target. The policy target ID is an operator-assigned identity bound to that socket and engine, not cryptographic daemon authentication. Protect policy/socket and prevent replacement or concurrent policy/source changes for the entire plan/apply window; do not treat a local socket path as proof of host identity.

Add `--secret-bindings <absolute-path>` to `plan`, `diff`, `up` and `validate`; with grants it is mandatory, as is policy. `validate` checks authoring/binding syntax and authorization only and must not claim runtime availability. `plan` and `diff` perform read-only availability preflight and inspect; `up` repeats all checks independently, not relying on a previous plan. `up --dry-run` has plan semantics. No auto-pull or mutation in preflight. Include selected services and dependency closure unless `--no-deps`; validate the entire declared graph and binding shape, but require source availability only for services actually selected. For full up check all granted sources. Complete secret preflight and existing ownership/plan checks for the selected operation before **any** image pull, orphan removal, stop, recreate, network/volume creation or start; subsets retain current no-orphan-removal behavior. A missing source for any selected service blocks the entire operation, including unrelated selected services. Recheck immediately before creation; failures after a pull or another mutation are partial failures, not a transactional guarantee. No check closes the race with an external administrator: source and policy immutability/quiescence are required throughout apply and container lifetime.

Both engines: the operator provisions each revision as a unique absolute host path, immutable for its lifetime. Every component from `/` through the parent is a real directory, owned by root or the trusted operator, not group/other writable, and has no extended access ACL or default ACL; reject symlinks and magic links. The final component is a regular file with link count one, no extended access ACL, and exact host UID/GID/mode from policy. Only root or trusted principals may own or write the file; for 0440 its group membership must contain only trusted principals. A dedicated non-login workload identity is acceptable only if untrusted host processes cannot assume it. These are operator provisioning obligations, not an assurance against a privileged host user. Reject inability to establish ownership, modes, ACLs, link count or traversal, including unsupported ACL/filesystem behavior. Traverse with directory descriptors and no-follow operations, open the final file without reading it, and `fstat` it. Never create, copy, chmod, chown, relabel, or delete a source; SELinux labeling and search/read permissions are operator-provisioned. Do not silently change ordinary container filesystem behavior. Read-only bind is required even for owner: mode alone is not read-only enforcement.

Policy UID/GID are **host** numeric IDs; grant UID/GID are **container** IDs. For rootful Docker with user namespaces disabled, and rootful Podman with default identity user namespace, require equality. Reject Docker rootless and any remapped Docker namespace. For rootless Podman, support only the daemon's unmodified default user namespace inherited by the container, with no per-container user namespace override or idmapped mount: identify the local daemon peer via Unix socket credentials, read that peer's `/proc/<pid>/uid_map` and `gid_map`, and translate each grant ID to exactly one host ID matching policy and file metadata. Require a verified same-UID local daemon peer, stable peer identity and readable maps; socket activation proxies, ambiguous mappings, unmapped IDs, unsupported namespaces, or inability to establish this relationship fail before mutation. Because the info API does not expose the daemon's default container namespace, the supported Alpha Podman service must use the protected, immutable-from-startup explicit `CONTAINERS_CONF` and restricted launch specified in [alpha-secrets-preflight.md](alpha-secrets-preflight.md); reject unresolved layers, modules, overrides and unsupported server versions rather than inferring defaults from peer maps. Exact peer identity requires Linux >=6.5 `SO_PEERPIDFD`, with no numeric-PID fallback. The pinned Podman server version's default container mapping must be established by real rootless CI; if it differs from the daemon maps or peer verification cannot work, reject rootless rather than guess. Do not alter a container's normal user namespace to make a grant work. A 0400 file grants access only to its mapped owner; 0440 also grants mapped group access. Actual workload UID/groups and directory/LSM access remain the operator's responsibility; preflight cannot guarantee workload readability.

Aliases to the same inode, including different logical names, policy entries, revisions, targets or services, share one file's permissions. Resolve and compare `(device,inode)` and require every selected grant referencing that inode to demand the same effective host UID/GID/mode; otherwise reject the entire operation before mutation. No per-grant ownership or mode is applied. An operator must not provision conflicting permissions for the same immutable source in separately applied stacks or services; Dill cannot discover all such deployments. Same inode with matching permissions may be mounted at multiple distinct allowed targets. Test both accepted matching aliases and conflicting aliases, including across selected services.

Use Docker's explicit bind-mount API and Podman's ordinary OCI bind mount with `ro`, not native secrets; do not auto-create missing paths. Inspect ordinary mounts on both engines for type/source/destination/read-only, and fail closed if the supported SDK/engine cannot expose these fields. No-follow/ACL checks do not eliminate path-to-daemon TOCTOU: trusted immutable directories and no concurrent replacement are mandatory through container lifetime. A same-path replacement by a different inode with equivalent metadata is not generally detectable: an existing bind may still refer to the old inode while inspect and current-path checks agree. Such replacement violates the operator's immutability obligation; Alpha does not require historical inode tracking or mounted-inode attestation. Inspect exposes paths. Runtime SELinux denial, external deletion or modification can still cause failure. Preserve externally owned files through every cleanup path.

### Lifecycle matrix

| Path | Alpha rule |
| --- | --- |
| `validate` | Syntax and policy authorization only, not availability. |
| `plan`, `diff`, `up --dry-run`, `secrets check` | Read-only preflight as specified; no mutation. |
| `up`, including Brine manual deploy and Git auto-sync | Independently checked preflight before any mutation; recheck before creation. |
| Dill `start` / `restart` | Reject the entire operation before any stop, pull or start if any selected service has grants **or** any selected existing owned container carries the reserved secret-enabled marker. Direct users to checked `up`; fail closed if selection/marker cannot be determined. Ordinary services keep their existing behavior. |
| Brine stack and direct container start/restart | Deny for secret-enabled deployments/containers, including when the recipe changed or is unavailable; use the persisted marker and trusted deployment record, fail closed on ambiguity. Direct users to checked `up`. No direct engine bypass. |
| `stop`, `down`, `teardown`, and corresponding Brine paths | Continue ownership-checked cleanup even if source, binding, or policy is unavailable; never delete source files. No availability preflight. Existing prompts and ordinary behavior remain intact. |

Persist the reserved label `dill.secret-enabled=true` on every container created with secret grants, protected against user labels, and retain a trusted Brine deployment record sufficient to detect secret-enabled containers even if configuration changes. A malformed marker is ambiguous and must fail closed for start/restart. The marker alone is not ownership or mount proof: ownership still requires `dill.managed=true`, the matching `dill.stack`, and a nonempty matching `dill.service`. Missing/uninspectable ownership or ambiguous classification fails closed for start/restart; do not infer safety from the current recipe alone. This is lifecycle routing metadata, not proof of mount state. External engine users can bypass Dill and are in the trusted-operator boundary.

Dill's `internal/stacklock` is an unwired local advisory primitive, not integrated deployment locking. Brine's runner currently serializes some operations by in-process path mutex only. Neither establishes cross-process/engine exclusion or protects source files. Alpha relies on the stated trusted-operator quiescence; do not claim locks exist or silently rely on them.

## Go adapter, hashing and drift

Add typed `SecretRequirement`, `SecretGrant`, `SecretBinding` and private resolved source types in `internal/config` and strict decode/semantic validation. Extend `orchestrator.Engine` with metadata-only host-file preflight/resolution and pass resolved per-service mounts into `StartService`; expose normalized secret mount observations in `LiveConfig`, implemented for both adapters. Do not put source values into Go structs, log sinks, command arguments or engine environment. SDK requests include only paths and mount settings. Extend schema validation, normalization and tests alongside `dill.pkl`.

Keep existing hashes unchanged for services with no grants. For secret-enabled services use a separately domain/version-tagged service hash (`dill-secret-hash/1`) over the existing normalized non-secret service payload plus sorted `(logical name, source ID, opaque revision, target, uid, gid, mode)` and target ID; never include contents or a content digest. The existing payload may itself contain legacy environment plaintext and must not be advertised as generally secret-safe. A missing/old secret hash causes one recreation; preserve legacy behavior for other services. Do not hash raw policy paths into public labels; compare them privately at plan time. Reordering declarations/bindings/grants is a no-op. A changed reference, revision, grant, target or permissions requires recreate. `--force-recreate` remains explicit and also recreates. Operator rotates by provisioning a new immutable revision, authorizing it, updating the binding, reviewing plan and applying; old running containers retain their old source until recreated. No automatic detection of in-place file content changes; such changes violate the policy, may be visible live and cannot be inferred from hashes.

Do not trust the hash label alone: compare desired resolved mounts with actual engine inspect on every plan. Both adapters map ordinary inspect mount type/source/destination/RW to authorized path/target/read-only; verify actual host file metadata and ID mapping again. Missing, extra, changed, writable, or uninspectable secret mounts cause recreate or a safe preflight error; don't mask ordinary mounts under secret targets. Unrelated mounts continue existing diff logic. Expose only logical grant/revision and generic change reasons in human/JSON plans, not source path. Legacy or foreign containers require existing ownership checks; never mutate by name after immutable-ID ownership validation. Inspect cannot prove workload readability or prevent malicious daemon replies; integration validates supported engines.

## Capability and safe responses

Add a separate static `dill secret-capabilities --format json` command, no config/engine access, returning exactly:

```json
{"contract":"dill.alpha-secrets/1","bindings":"dill.secret-bindings/1","policy":"dill.secret-policy/1","engines":["docker-host-file","podman-host-file"]}
```

This advertises implementation of this contract, **not** target readiness, actual availability, or protocol operations. Unknown flag/format fails. When operator `--secret-target` and `--secret-policy` enable secret mode, Brine requires the exact known contract, both binding/policy versions and engine entry before every Brine plan, up, start or restart, including apparently ordinary or unmarked stacks; malformed, missing, old or unsupported discovery fails closed with upgrade guidance. Legacy old-binary behavior is available only with secret mode explicitly disabled, and persisted known-secret records still fail closed when configuration is removed. Cleanup remains independent of secret availability and capabilities. The new Dill must reject grants without matching authorized bindings before mutation. Do not fall back to `caps`, `version`, parsing help, or legacy deployment. No claim that metadata protocol runs this feature.

Add `dill secrets check --secret-target ID --secret-bindings ABSOLUTE -f CONFIG --engine ENGINE --engine-socket ABSOLUTE --format json` (global flag ordering as existing CLI requires). It runs the same full-stack read-only authorization/availability preflight without pulling or creating anything. Success is `{"contract":"dill.alpha-secrets/1","status":"available"}` exit 0; failure is `{"contract":"dill.alpha-secrets/1","status":"unavailable","error":{"code":"SECRET_UNAVAILABLE","message":"Secret configuration or source unavailable."}}` exit 1. No identities, paths, parser text, Pkl stderr, SDK errors or input echo on stdout/stderr, including authorization denial, malformed input, timeout and unavailable engine; wrong invocation also gets this fixed failure. Do not distinguish missing from unauthorized to Brine. Use bounded output and timeout; no generic logging of wrapped errors. All secret-related errors in plan/up/validate are likewise fixed and identity-free; suppress raw Pkl/engine errors on this secret path, including debug logs. General legacy commands remain outside this guarantee. Status is a point-in-time check, not authorization to skip apply preflight. Plan exit remains 1 on drift, diff 0 on drift, errors nonzero.

## Brine handoff and packaging

Brine's existing `internal/dill/runner.go` removes `BRINE_AUTH_PASSWORD`, `BRINE_API_TOKEN`, and `BRINE_AUTH_USER` from subprocess environments but inherits other variables; it captures/streams combined output, and current API/Git sync use that runner; require discovery, isolated per-stack bindings, and the appropriate lifecycle-matrix checks on secret-enabled paths, including auto-sync; cleanup must not require source availability. Run Dill with an explicit minimal environment: fixed PATH/locale, operator-configured Pkl and policy paths and engine endpoint only; no inherited Brine process env, Git tokens, registry credentials or arbitrary stack env. The trusted launcher may provide narrowly scoped engine authentication if independently configured, but Alpha local sockets need none. `--env-file` remains legacy and is not a secret binding. Protect bindings and workspace against other OS users, authorize all UI/API/plan/SSE/history access consistently, and never show source inventory, values or host paths. Availability responses expose only the fixed status. Deny cross-stack binding file selection; derive the file path from Brine's internal deployment ID, not caller-provided paths. Target and stack IDs must match the selected deployment and operator policy. This isolates references in the UI, not mutually hostile Pkl or workloads.

UI/API edit only the structured binding document (logical name, authorized opaque source ID and revision); no regex rewrite of arbitrary Pkl. The recipe author adds typed declarations/grants using their normal editor; Brine does not infer or alter arbitrary Pkl. Validate names and version on input; write atomically with restrictive permissions and retain references only in history. Never accept plaintext upload. Do not route raw Pkl diagnostics, backend errors or unbounded subprocess output into the reference UI. Existing unrestricted text editor and workload logs are not guaranteed secret-free.

Keep a per-deployment **draft** binding separate from the **active**, explicitly approved binding. Saving or previewing a draft never changes the active binding; manual deployment and Git auto-sync use only the active binding, or fail closed if none is approved. Preview runs read-only Dill plan against the candidate and displays its result. Explicit confirmation activates and applies exactly that previewed candidate, not a later draft. Changes to the draft, evaluated configuration including imports, target, policy, or relevant live state invalidate the preview; require a new preview rather than applying a stale approval. Before activation, revalidate the inputs and repeat the read-only plan; if unchanged inputs and the displayed plan cannot be established, reject confirmation. This approval check does not replace `up`'s independent preflight or guarantee a transaction: if apply fails after activation, report failure and any partial mutation; the approved binding remains active for subsequent checked operations.

Serialize Brine-managed draft edits, preview, confirmation/activation, manual deployment and Git pull/deploy for the same deployment so that auto-sync cannot consume a draft or change plan inputs between confirmation checks and activation. A single Brine process may use a per-deployment lock covering these paths, including workspace changes; fail closed rather than run an uncoordinated path. This does not claim Dill's unwired lock provides cross-process protection: trusted operators must exclude external writers and additional Brine processes for this Alpha, consistent with the existing quiescence boundary. Approval covers references and the previewed operation, not secret values.

Brine Dockerfile currently bundles Dill `0.5.0`; it must remain honestly incompatible until a release includes this contract. For paired CI build Dill from the exact candidate commit with repository `make build`, copy `bin/dill` into a CI-only Brine image stage or mount it read-only at a separate absolute path and select it using Brine's existing `--dill` option; ensure binary/architecture and Pkl schema under test come from that same candidate. Pin candidate commit and verify checksum of transferred CI artifact. Run discovery on the installed binary before tests. A separate test must run the unmodified 0.5.0 image and assert feature disabled/explicit upgrade error, not success or a fake capability. No release, default-version bump, or promise of bundled support until paired final-head CI and reviewed release.

## Required paired evidence and blockers to rollout

Dill unit/contract tests: Pkl positive/negative fixtures, strict JSON duplicates/unknowns, duplicate grants/bindings, cross-stack and cross-target denial, environment isolation, mount collisions, invalid IDs/modes, no authority from Pkl, fixed errors with sentinel in parser/SDK/Pkl failures, zero source-byte reads, deterministic hash ordering/revision change/legacy migration, no secret bytes or value hash in secret-derived labels, config references and plans. Spy operation ordering for full and subset up, dependencies and `--no-deps`, `always` and `missing` pulls, orphan and recreate: one unavailable selected grant means zero mutation; unselected unavailable sources do not block subset; no orphan deletion on subset. Test post-preflight failure as partial, never false atomic success.

Dill disposable Linux engine integration CI, separate Docker and Podman jobs: provision only synthetic sentinels and dedicated temporary sources; test create/read as requested non-root UID/GID, unauthorized UID denial and read-only mount; check plan noop and live inspect mapping; rotate to new revision and verify planned recreate and new value; missing/misconfigured source blocks pull/orphan/recreate; require drift or rejection for observable violations, including a missing source, symlink replacement, changed file metadata, and changed inspected mount source/settings; do not require detection of same-path metadata-equivalent inode replacement; verify cleanup retains sources. Test symlink in every component, nonregular files, hard links, permissive modes/ACL, and inaccessible file; require a real rootless Podman CI runner demonstrating the exact supported default mapping, including a mapped non-root UID/GID that reads 0400 or 0440, and explicit rejection of unmapped, mismatched and unsupported mappings before mutation. On each supported rootful mapping also prove non-root authorized access and unauthorized UID/GID denial. Attempt chmod followed by write as the file owner and verify both engines enforce the read-only bind. Test matching and conflicting inode aliases within and across selected services. Docker rootless and remote/VM targets must reject. Search output, labels and captured plans for synthetic value and its low-entropy hash; never print container read output in CI. Engine inspect can expose metadata; do not claim it hides mount paths. Use isolated CI engines only; no unverified local engines.

Brine paired tests use candidate binary/schema, disposable policy and separate stacks/targets: reference-only UI/API/history/SSE, same-name source denied across scope, unavailable status without path/name/error leakage, no plaintext sentinel or value hash in captured artifacts, restrictive file permissions, no arbitrary Pkl rewrite, no ambient credential inheritance, plan-before-rotation, all manual and Git sync paths fail closed on old/malformed capabilities. Test that saving or previewing a draft cannot rotate a running deployment during concurrent Git sync or manual deployment; these use only the approved active binding or reject if none. Confirm the exact previewed candidate, reject stale confirmation after draft/config/import/target/policy/live-state changes, and test serialization with Git workspace updates and apply failure after activation. Exercise the lifecycle matrix including changed/missing recipes, persisted marker, direct container actions, restart before any stop, and source-unavailable cleanup; prove ordinary container behavior remains unchanged. Verify `0.5.0` negative packaging case separately. Run Dill `make build`, `make test`, `make vet`, `make validate` plus the override Pkl evaluation documented in `AGENTS.md`, and both engine integration jobs; run Brine build/vet/unit and browser tests plus candidate/old-image integration in paired CI. Record exact commits, commands, engine versions and skipped cases. Contract fixtures must distinguish synthetic tests from supported runtime features.

**Material rollout gates:** ordinary bind create/inspect fields on both SDKs and the specified rootless Podman peer/default ID mapping must be proven on pinned supported versions; Linux ACL/no-follow checks and local-daemon assumptions must be implementable on the supported filesystem; secret-safe suppression must cover every secret-enabled Brine execution path; CI must provide isolated Docker and rootless Podman. If any cannot be established, reject that target or withhold the Alpha feature; do not silently weaken it. Admin-controlled source replacement between checks and engine use remains an explicit trust limitation, not a solved atomicity guarantee.
