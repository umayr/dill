# Brine signed monitor: host and aggregate memory v1

**Proposal for Cora and parent review. Default off and unadvertised.** This proposes a Brine-specific JSON reader of the immutable [`metricsmodel.Snapshot`](../../internal/metricsmodel/model.go) from [Dill #152](https://github.com/umayr/dill/pull/152), not a second collector or a replacement for the separate [Prometheus #151](https://github.com/umayr/dill/pull/151) scrape contract. It would supplement the production transport proposal for [Dill #150](https://github.com/umayr/dill/issues/150) if jointly approved. It does not share the Prometheus scrape credential or TLS trust model. No implementation, listener or run is authorized by this document.

The [earlier Gate 1 matrix](https://github.com/umayr/dill/issues/150#issuecomment-7058773020) and [parked Gate 2](https://github.com/umayr/dill/issues/150#issuecomment-7059145840) concern a provisional **per-container** candidate, with rows and representation/scan coverage. Gate 2 did not run; the old vectors are not aggregate-v1 conformance or activation evidence. This contract has no rows, per-container query, identity, labels, pagination, truncated totals or per-container fallback. It does not close [Brine #185](https://github.com/umayr/brine/issues/185) or gate remote deployment/recovery.

## Authority and rollout gate

Keep the existing private, direct, leaf-pinned HTTPS enrollment and the exact `POST /v1/session` `brine.agent.read/1` exchange and `brine-agent-session/1` proof bytes unchanged. Brine must verify a fresh challenge against the enrolled endpoint, TLS pin, signing key/fingerprint, engine ID/kind/socket, daemon ID and binding generation, then retain the verified process epoch. The nonce proof authenticates the agent; it does **not** authenticate or authorize a caller. Do not add metrics fields to that proof, reuse a deploy grant, or change pairing, Unix listener, inventory, inspection, logs, reveal, staging, or journal behavior.

**Metrics entitlement and activation remain undecided.** Dill and Brine owners and the target operator must decide whether explicit per-target host opt-in may grant these aggregate reads to **all holders of the existing monitor credential for that target**, or whether a narrower, independently provisioned metrics entitlement is required. The examples model the former conditionally, after [#149's separated authorization dispatch](https://github.com/umayr/dill/pull/149) is accepted and qualified on the exact pair; they authorize neither choice nor activation. This is not a grant to broaden today's shared bearer: the assigned base does not establish #149 integration. If the broader monitor-role entitlement is rejected, keep the capability absent and review a new authorization design before implementing/enabling it. Brine must also enforce its own operator/viewer authorization to that specific target; a browser user never receives the agent credential. Neither signing nor discovery is a permission grant.

The monitor credential is accepted only by the monitor allowlist; deploy (including any grant combination), scrape-only and unrecognized credentials never gain metrics access. No automatic credential swapping, legacy shared-bearer fallback, re-enrollment, pin relaxation, Unix/direct-engine fallback, or probing the scrape listener. Authenticated requests on disabled or unqualified targets do not advertise v1. In this candidate, activation and role configuration are fixed for the process lifetime; disabling or revoking at the agent takes effect by controlled restart, producing a new epoch. Clear Brine's live view and discovery immediately on local target disable or revocation; the short freshness cutoff bounds old displays while Brine has not yet observed a remote restart. Runtime activation still follows the [production no-go record](https://github.com/umayr/dill/issues/150#issuecomment-7059197806): separate implementation approval, independent contract review, exact release-pair role/compatibility checks, qualified disposable native Linux Docker evidence (authority/locality, source age, bounds/cancellation under churn), and explicit operator activation. Podman, proxied daemons and unproven locality are not qualified in v1.

## Proposed endpoints and binding

After the ordinary signed session, use the same enrolled origin and monitor bearer for these two exact private HTTPS routes. Paths are literal; no encoded variants, query (even empty), redirects, or alternate methods. Both require exactly one of each `X-Request-Id` (client-generated fresh cryptorandom 128-bit ID as 32 lowercase hex, never reused), `X-Brine-Binding` (canonical decimal uint64 session generation, nonzero), `X-Agent-Epoch` (the verified session epoch) and `Content-Type: application/json`. Header names are case-insensitive; reject duplicate instances or comma-folded lists for singleton fields, not just conflicting values. Reject content coding, duplicate keys, trailing values, malformed UTF-8, nulls, unknown keys and wrong scalar types. The object keys and string values are case-sensitive. A well-formed capability identifier is 1–64 ASCII characters in `[a-z0-9./-]`.

| Operation | Path (`POST`) | Exact request JSON | Signed `data` on HTTP 200 |
|---|---|---|---|
| Discover | `/v1/monitor/capabilities` | `{}` | `{"capabilities":["brine.agent.metrics.aggregate/1"]}` |
| Sample | `/v1/monitor/metrics` | `{"capability":"brine.agent.metrics.aggregate/1"}` | Object below |

The two routes are both absent when disabled/unqualified; no wildcard or inherited prefix grant. Discovery makes no collector/engine calls. Brine only samples after validating signed discovery for the same enrollment, generation and epoch. If discovery lacks the exact identifier, or is unavailable, do not sample; negotiate no implicit version or legacy path. A changed field set or semantic change to this sample needs a new capability/version, not reinterpretation of `/1`. Discovery may list additional distinct capability strings under a future separately reviewed extension (at most eight, each 1–64 ASCII characters in `[a-z0-9./-]`); clients match only the exact identifier they implement.

For both successful replies, use `Content-Type: application/json`, `Cache-Control: no-store` (also on errors), no compression and a single bounded JSON object with exactly `version: "brine.agent.read/1"`, `requestId` echo and `data`. The proposal authenticates the new results separately with a detached `X-Dill-Monitor-Signature` header: canonical unpadded base64url of exactly 64 Ed25519 signature bytes, using the enrolled agent signing key. The signed input is:

1. ASCII `brine-agent-monitor-response/1` followed by NUL.
2. Length-prefixed UTF-8 strings, in order: `POST`, literal path, request ID, enrolled agent ID (lowercase SHA-256 hex of the signing public key), enrolled engine UUID.
3. The binding generation, unsigned 64-bit big-endian.
4. The length-prefixed UTF-8 epoch, followed by the **32 raw bytes** of SHA-256 of the exact uncompressed HTTP response body bytes, including any final newline.

Each length prefix is an unsigned 32-bit big-endian byte count; no padding or JSON reserialization. This domain signs only HTTP 200 responses to the two exact requests above; status, path, request and response must also meet the contract. Brine checks the bounded bytes and proof against the enrolled key and its outstanding request's **local** verified session tuple, before parsing or displaying data. No key or target field in the response can select a different enrollment. Session verification already binds the engine kind/socket/daemon ID and key to that epoch; sample signing must use the admitted epoch and must not substitute a new one. Reject missing, duplicate or invalid proofs, unknown versions, bad echoes, wrong generation/target/epoch and any late, unsolicited or duplicated completion. Brine keeps at most one active metrics extension attempt per enrollment; starting a replacement, canceling, timing out or retiring the session invalidates the old request slot before any new attempt. Even a correctly signed old success or old error must not update the display, discovery, backoff or session state. Do not reuse the request ID for a retry. Signatures are not caller grants, standalone portable attestations of host locality, or evidence of measurement age outside the request window.

After bounded HTTP intake/framing, authenticate and check route availability and role before reading the extension body; then validate extension headers, binding/body/version and admit work. A denial before admission performs no collection. Check the enrolled daemon and the acquisition-wide prerequisites for **each** sample; matching a daemon ID or socket pathname alone proves neither acquisition identity nor native procfs locality. A live daemon mismatch is a binding failure, not a partial sample. Abort on binding/epoch change before response and discard in-flight results once Brine observes a target rebind, revocation, restart or epoch change.

A non-200 from stock `/v1/session` cannot install a session and retires the prior session for metrics use; stock request, envelope and proof behavior stay unchanged. The extension cannot interpret a stock non-200 as `BUSY`, proof of a fresh epoch, or permission to keep using an old epoch. Keep the extension parser and bounds separate from the stock session exchange; do not route extension errors through the stock non-200 session retirement path indiscriminately. Here, **retire** clears the verified session for metrics, its discovery, live values and outstanding request slot. **Rediscover** means a new bounded discovery on a verified session, never an immediate sample retry. If retired, obtain and verify an ordinary session first, only where allowed below.

| Extension result | Handling (for the still-active attempt only) |
|---|---|
| `401` / outer `403` | Missing/invalid credential or denied role. Retire for metrics and stop automatic metrics attempts pending operator review; no alternative credential. |
| `403` + valid `EPOCH_MISMATCH` | Retire. At backoff expiry a previously qualified target may perform an ordinary nonce challenge with the same enrollment/credential. Rediscover only after proof succeeds; no sample until that discovery succeeds. |
| `404` / `501` | Clear capability and live data; report unavailable/unsupported, not an empty observation. Suspend sampling; scheduled rediscovery after backoff may use a still-verified session. No old-path or version fallback. |
| `400` / `413` / `431` | Invalid shape or body/header limit. Clear live values, stop automatic extension attempts pending client/operator review. |
| `409` | Binding changed; retire and stop automatic metrics attempts pending operator investigation. Never auto-accept changed identity. |
| `429` / `503` | Clear live values and report a gap; on a bounded recognized result keep verified session and discovery, defer the same operation to backoff. No immediate handshake, queue, retry, or cached success. |

Inside the extension, errors use `application/json` and exactly `version: "brine.agent.read/1"`, `requestId` (echo if valid, otherwise `""`) and `error: {"code": "…"}`. Fixed codes: `INVALID_REQUEST` (400), `EPOCH_MISMATCH` (403), `BINDING_CHANGED` (409), `LIMIT_EXCEEDED` (413), `UNSUPPORTED` (501), `BUSY` (429), `OBSERVATION_UNAVAILABLE` (503). For a matched request only an exact status/code pair, valid shape and matching nonempty echo can drive recovery (a blank error echo is diagnostic only). Outer dispatcher/framing denials may be fixed status-only or have a bounded fixed plain-text body; never decode one as an extension envelope. Non-200 has no metrics or signature and is diagnostic on the pinned connection, not a signed result. Do not log raw responses. A timeout or ordinary transport interruption from a still-valid target clears live values and defers the same operation; a TLS trust error, bad proof, malformed/over-limit reply or unexpected status retires metrics state and stops automatic attempts for investigation. A stock session non-200 during re-verification leaves metrics retired; only a transient unavailability/rate-limit status may defer that same session operation, not a denial or protocol/binding failure.

Provisional retry schedule: one deferred attempt per target, no queue, not before the later of normal polling and a client-side exponential delay of 5, 10, 20, 40, then at most 60 seconds after failure. Count consecutive failures in that recovery chain; reset after the pending operation recovers (for epoch recovery, after verified session **and** verified discovery). v1 does not use `Retry-After` hints to schedule retries; local backoff applies regardless of a supplied hint. No recovery path can alter enrollment or permissions, enable a disabled target, request a deploy/scrape credential, or trigger deployment. Do not interpret any metrics result as workload health or as a deploy, recovery or journal outcome.

## Immutable snapshot and freshness

Project exactly **one** `metricsmodel.Compute` result. The adapter must not repair it from a second read, cache, prior poll or another engine. A safely completed acquisition may have one failed source; an acquisition that did not safely conclude within bounds invalidates both. Return 200 only when `Usable()` is true, otherwise 503 without any count, status or measurement payload.

| `data` field | Presence and value |
|---|---|
| `capability` | Always `"brine.agent.metrics.aggregate/1"`. |
| `coverage` | `"complete"` if both memory families are present, otherwise `"partial"`. |
| `hostMemoryComplete` | Boolean equal to presence of both host fields. |
| `ownedMemoryComplete` | Boolean equal to presence of the aggregate byte sum. |
| `hostMemoryTotalBytes`, `hostMemoryAvailableBytes` | Both or neither. One verified native same-read `MemTotal`/`MemAvailable` pair, kB × 1024 checked, positive total, available ≤ total. Available is an estimate, not free bytes. |
| `ownedRunningContainers` | Optional count from one current exhaustive inventory with verified candidate IDs, running status and ownership classification on the enrolled daemon across stacks. A verified stopped container is excluded. An ambiguous inventory (including missing/duplicate candidate IDs, unknown eligibility/ownership or contradictory verified ownership for the same current incarnation) means **no count and no sum**. |
| `ownedMemoryUsageBytes` | Optional sum of raw Docker `memory_stats.usage`, not CLI working set or unique resident memory. Requires a known positive count and proven current samples for the entire same eligible set, linked to verified identities/incarnations. If only the reading's link to the inventoried incarnation is unverifiable (including replacement during sampling), the independently verified inventory count may remain, **never** a subset sum. |

All numeric payload measurements are exact JSON integer tokens (decimal digits, no exponent, fraction, sign or leading zero except `0`), in `[0, 9007199254740991]`. Overflow/range errors withhold the affected family, not an independent valid measurement. Omitted means unknown/unavailable unless a known count of zero makes the sum **not applicable**. A fully verified empty inventory has count `0` and no sum; if the host pair is known this is still `partial`, not a failure. Measured zero usage requires a nonempty, fully measured set. Count alone (including zero) never warrants 200. Brine rejects data that violates the field allowlist, presence/flag rules, range, pair ordering or host-byte divisibility by 1024. There is no `null`, sentinel zero, boot/time-of-incarnation field or raw source error.

Source freshness and display freshness are distinct. Every published value must have model-verified source evidence within one request-contained monotonic acquisition window; receipt time, Docker HTTP success, or a wall clock comparison is not source evidence. The source timestamp, candidate IDs, sample identities and evidence stay private to acquisition. If source age cannot be established, withhold that source. The two sources need not be simultaneous; neither family is an atomic engine inventory.

Brine uses its own elapsed monotonic time (must account for suspend, or invalidate on resume). Bound the age of **every** accepted reading conservatively by `now − requestStart`, where start is just before sending the sample request. The sign-and-echo plus the request-contained collection rule permit this bound without comparing wall clocks or transmitting timestamps. Keep the following trial clocks distinct; numerical thresholds are provisional, not a promise of continuous data or production defaults:

- **Display age:** a verified reading remains current only while its age upper bound is **< 5 s** and session/discovery remain valid. Expire it even if no poll runs. At cutoff show stale/gap, and clear live values immediately on a failed newer poll (including 429), identity invalidation or unverifiable elapsed time.
- **Admission cooldown:** minimum **5 s** between admitted sample starts on the agent monotonic clock, not between completions and not a display TTL. A refused attempt does not move the start marker. Any admitted attempt, including failed/canceled, does.
- **Latency:** acquisition ≤ 1 s; server delivery phase ≤ 250 ms inside the server's own 2 s absolute request cap. Brine accepts the fully received and verified reply within **2 s** of its own request start (inclusive), not from arrival or acquisition completion. A fresh sample at receipt can have less than 5 s left before expiry.

Even at an exact 5 s polling interval, the previous sample can expire before its replacement arrives. Shared Brine/Prometheus admission can lengthen gaps: either reader can win the next slot, so one may be refused repeatedly. Accept visible stale gaps; never synthesize a successful read from cache, reset the sample's age or weaken the cooldown to mask them. Do not fill omitted fields from older data or show a receipt timestamp as sample time. Optional Brine history is separately authorized, gaps included; Dill has no sampler, history, persistence, replay or backfill.

## Work and disclosure ceilings

Proposed qualification ceilings, not performance evidence or rollout defaults. Enforce before allocating/dispatching beyond a cap; client cannot tune them. A request can fail earlier, but a started acquisition that exhausts a global budget is not a safe partial result.

- Extension only: max 512 UTF-8 body bytes/request, max 4 KiB response body (including errors), max 8 KiB header fields in **each** direction. Count decoded field-name bytes + field-value bytes + 4 per field occurrence, including duplicates and authorization/signature fields, independent of transport compression/framing. Use a bounded HTTP parser before field expansion/allocation (including start line/transport framing limits); a handler-only check after unbounded parsing is not a cap. Refuse over-limit requests with 431 for headers or 413 for body when a bounded reply is safe, otherwise close/reset; Brine abandons oversized replies including errors. Keep these extension limits out of the stock session decoder; preserving the stock session contract while demonstrating the early cap on the shared origin is a transport implementation gate, not a reason to rely on a late handler check.
- No HTTP body compression: Brine sends `Accept-Encoding: identity` and disables transparent decompression; both ends reject any `Content-Encoding` field (even `identity`) and validate framing before reading. Reject ambiguous framing, conflicting/duplicate length fields and trailers. Bound bytes and read time even when no length is advertised; success response is fixed-length, with any final newline included in its length and signature. Bound JSON parsing to depth 4 (root counts as 1) before descending further; stop on duplicate keys, excess bytes or any schema violation. Pre-serialize, size-check and sign before sending success headers; if delivery has started and fails, abort/reset. Brine rejects incomplete bytes within its original deadline, not a restarted timer.
- Max one admitted extension request per agent, including discovery and response delivery; no queue. At most one discovery start per second, no collector work. If both surfaces are ever approved, Brine samples and Prometheus scrapes must share one agent-wide sample admission slot, the 5 s start cooldown and the same upstream budget for that daemon; hold the slot through delivery and until canceled work is quiescent. Discovery does not consume the shared sample cooldown. Do not qualify concurrent independent collectors without coordination. Existing read routes are not new metrics backends; account for their load and the unchanged session endpoint separately in qualification.
- Per sample: max 1 s monotonic acquisition, max 250 ms per upstream call, max 2 upstream calls in flight; max 100 enumerated candidates (no silent truncation), max 20 eligible samples, max 4 MiB cumulative upstream read bytes, max 128 upstream operations including failed/canceled attempts, identity checks, host reads, enumeration, classification and stats. No automatic collector retry or background continuation. Cancel on disconnect/deadline; if upstream cancellation cannot be bounded, do not release admission for overlapping work until it is quiescent; do not activate without evidence about daemon-side costs. Admission refusal is 429; exhausting the acquisition budget is 503, not complete-empty. A safely completed read with independently invalid/unavailable source evidence can produce a partial as defined above.
- No writes, shell/exec, env, log or mount content, raw engine errors, identity rows or arbitrary labels in this contract. Internal labels/identities may classify eligibility only; never return them. Metrics reveal host capacity and workload size even without IDs. Do not log credentials, session/response proofs, raw payloads, per-container source evidence or host paths. Keep metrics separate from deployment permissions and audit/history.

## Review evidence

[Synthetic examples](../testdata/brine-monitor-aggregate-v1/examples.json) are decoded, inert vectors: no wire requests, credentials, keys, signatures, or runtime mocks. `acquisitionAttempts` counts admitted sample attempts, including the sample's live daemon check, not individual reads or the ordinary session handshake. `data` is the full proposed success payload, not an HTTP envelope. Receipt cases vary proof and elapsed-time outcomes for the named success. Timeline cases use aligned synthetic monotonic clocks for arithmetic only; the real client and agent do not compare clock values. Recovery/parser cases and known-answer requirements are expected decisions, not executed protocol or cryptography.

**Cross-language known-answer gate (not run):** before shipping, Dill and Brine must independently encode and verify the same frozen offline vectors, including every implementation language that encodes or verifies these proofs. Publish a reviewable synthetic manifest with public-only test verification material, literal body bytes in hex (or equivalent lossless encoding), the exact signing preimage bytes, SHA-256 body digest, expected signature and verdict. Require both discovery and sample positives; independently check the known answers rather than merely round-tripping a shared encoder. Test generation `1`, `2^53+1` and `2^64−1` as exact unsigned 64-bit values (no floating-point conversion in stock session verification, header comparison or signature input), noncanonical decimal and overflow rejection, and a one-field generation substitution. Include swapped proof domains (stock `brine-agent-session/1` versus extension), extension route/ID/target/epoch substitutions, duplicate and folded request/proof headers, exact bytes with whitespace plus trailing newline, and whitespace-only mutation with the same signature (reject, even if JSON decodes identically). A valid proof for a superseded request must still be rejected by the client state machine. Keep a frozen stock `/v1/session` nonce, envelope and proof vector and verify the bytes and legacy behavior with the extension off and on; do not revise the stock format to make the vectors pass.

After joint review, separately approved paired tests must cover that gate, wrong-role/stale/misbound/unsupported denials before collection, #152 parity, bounded parser/framing, state retirement/backoff and contention/429 gaps with both readers. Prove freshness, operation under shared contention, and work bounds natively before advertising. Open decisions are the entitlement and explicit activation above. Select an independently reviewed bounded transport implementation that preserves stock session behavior, and validate display age, poll/backoff, latency and cooldown as separate operating limits before choosing supported defaults. No provisional Gate 2 evidence transfers automatically.
