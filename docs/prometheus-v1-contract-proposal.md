# Private Prometheus scrape v1 — contract for review, not shipped

Decided: a separate opt-in private HTTPS listener with SAN-valid TLS and a dedicated scrape-only bearer; no insecure fallback. Host/aggregate only. Existing Brine signed monitor session, deploy grants, journal, and Unix socket stay unchanged. No service is provisioned by this design.

## Wire and measurement

Exactly GET /metrics, no query or redirects. Baseline text/plain; version=0.0.4; charset=utf-8, HELP and TYPE gauge, no explicit sample timestamps, no compression initially, Cache-Control: no-store. Support absent Accept, */*, or acceptable Prometheus text; negotiate truthfully, 406 when explicitly excluded. No OpenMetrics/protobuf in v1. Private registry only. No variable labels, instance names, IDs, raw errors, per-container output, default runtime collectors or samples from a prior scrape. Prometheus owns its target labels and up.

| Family (all gauges, no labels) | Presence and meaning |
|---|---|
| dill_host_memory_total_bytes | Native Linux MemTotal, kB × 1024, overflow checked. Only with proven locality, valid same-read pair and credible source age. |
| dill_host_memory_available_bytes | Native MemAvailable, same conditions. Estimate, not free bytes. Publish both host values or neither. |
| dill_owned_containers_memory_usage_bytes | Sum of raw Docker memory_stats.usage across all eligible containers in the enrolled daemon. Not unique resident RAM or a Docker CLI working set. Only after exhaustive bounded enumeration and full verified sampling. For v1 omit the byte sum for an empty set: zero bytes is published only for a nonempty fully measured set whose sum is zero. Any missing reading/ambiguous ownership or incarnation = omit sum. |
| dill_owned_running_containers | Count of eligible running, Dill-owned containers across stacks, not replicas declared in config. Only when enumeration and ownership classification were exhaustive; can remain known when a memory reading fails. Explicitly exclude stopped containers; changing/uncertain identity invalidates affected measurement. Not an atomic engine inventory. |
| dill_host_memory_collection_complete | 1 if the host measurement pair is published, otherwise 0. Availability flag, not a memory quantity. |
| dill_owned_containers_memory_collection_complete | 1 when the whole-set memory sum is published; otherwise 0. Never use 0 as a substitute for an unknown byte measurement. |

The count and byte sum use exactly the same eligible set from one acquisition: running containers whose Dill ownership and enrolled daemon identity were verified. If enumeration or ownership classification is incomplete, publish neither count nor sum. If the set is fully known but a reading is missing or its incarnation changed during sampling, the enumerated count may remain, not the sum. Do not count only containers that returned stats.

Perform kB × 1024 and byte addition in checked integer arithmetic before converting to a Prometheus float64 sample. For v1 accept integer samples only in [0, 2^53 − 1] inclusive (a conservative contiguous safe range); never round, saturate or wrap an out-of-range value. A failed host conversion withholds both host gauges; an invalid aggregate withholds the sum and clears its completeness flag, not an independently verified count. Boundary tests: max accepted, max + 1 rejected, multiplication overflow, individually valid summands exceeding the safe limit, and count known with one missing sample. No count-only or status-only success.

200 only if at least one numeric measurement (host pair or qualified complete aggregate, over a nonempty eligible set) is trustworthy; auxiliary count/status alone does not warrant 200. On partial 200 publish only justified measurements plus the two flags. No denominators inferred from truncated rows. If no usable measurements, identity verification fails, or acquisition cannot complete safely, 503 without metrics. No data collection on auth failure: absent/invalid/revoked token 401, other routes unavailable, no redirects/challenges that disclose credential material. A Brine or deployment token is not a recognized scrape credential. The listener must not load deployment or monitor secrets just to classify a denial; provision a distinct secret out of band. 429 for concurrency/cadence refusal, no hidden queue/retry. Success is not workload health. No sample-age metric until a credible source-age contract exists; scrape time is not source time.

## Identity, lifecycle and bounds

Explicit listener address, trusted cert chain/key with appropriate SAN for scrape hostname/IP, separate private token file, enrolled local daemon identity. Default off; invalid files, wildcard/public bind or accidental endpoint sharing fail closed. Separately validate client trust and hostname (not Brine pin). Authenticate before collection; revalidate daemon identity for every acquisition. A signed daemon ID or Unix path does not alone establish host procfs locality. Qualify the native runtime and identity boundary before advertising any source. Acquisition uses bounded observation window; discard readings not proven current for that window. No cache/history/background work. Operator owns CA issuance/renewal, restricted files and firewall. Proposed v1 reload by controlled restart: replace files atomically, no default grace token, old credentials must fail after restart, never regenerate or replace Brine trust. Rotation is not verified yet.

Trial budgets only: 1 concurrent acquisition per agent, no queue; 5 s minimum start interval, 1 s monotonic acquisition, ≤250 ms per call, ≤2 concurrent upstream calls, ≤100 enumerated candidates, ≤20 eligible for sampling, 4 MiB aggregate upstream bytes, 32 KiB encoded response, 250 ms write budget. Charge attempts including cancellations; bounded parsing and transport. Pin a separate absolute request deadline. Agent limits do not prove dockerd work is bounded/canceled. A native qualification report must explain upstream behavior, total call ceiling, source freshness and sufficient operator headroom before selecting production limits. No sandbox or native tests authorized here.

## Implementation slices & gates

1. Isolated dependency spike: evaluate official client_golang v1.24.1 (Go 1.25.0) versus v1.25.0 (requires Go 1.26); Go requirement compatibility is not a passing build or advisory check. Review MVS delta, go.sum provenance, license/advisories, Darwin/Linux size and tests. Specifically examine x/sys v0.30→at least v0.47, compress v1.17.7→at least v1.19.1, protobuf v1.33→at least v1.36.11. Reject unreviewed toolchain bumps. No installation here.
2. Offline pure snapshot + renderer with fixed descriptors on a private registry. Use client_golang/prometheus/promhttp.HandlerFor only if its actual negotiation matches the text-only contract; otherwise encode gathered DTOs with official prometheus/common/expfmt TextEncoder and explicit protocol negotiation, not hand-written samples. Bound output before sending headers; cancellation belongs in acquisition, not the encoder. Test exhaustive empty, exact zero, omitted data, missing/stale source, overflow, ownership change, and bounded cardinality over repeated scrapes.
3. Implement authentication/listener in an isolated branch, disabled by default. Verify stock routes unchanged, denial has zero engine calls, shutdown, duplicate/expired credentials, correct certificate identity, no leaks. Review independently before exposing any target. Distinguish validity of server cert from token expiry: opaque file tokens have no implicit expiry.
4. Separately approved disposable static/promtool + pinned real Prometheus v3.16.0 candidate scrape test, including Accept/content type, TLS SAN/CA rejection, token rotation, partial/failed scrapes and series behavior. promtool alone does not verify target auth or native collection. Later qualified Linux Docker drill for locality, freshness, latency, churn and daemon-side costs. Publish supported tuple and measured limits; explicit activation approval last. No code, listener, native qualification or release implied.

Operator input before rollout: who issues/rotates certs and token; private address/DNS and firewall owner; required Prometheus versions, expected scrape interval and maximum host size; authorized disposable native target/operator and service impact budget. Recommend manual provision/restart first; no CA creation or real credentials requested. Brine optional history is independent; no agent persistence.
