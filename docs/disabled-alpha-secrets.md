# Disabled Alpha disposable and strict-secret entrypoints

The Alpha disposable-volume profile (`up --alpha-disposable`, including an explicit `false`) and strict file-secret operations are disabled. Secret capability discovery no longer advertises an available implementation. Secret selectors, proof flags, `DILL_SECRET_POLICY` (even if empty), and `secrets check` fail closed. Configurations declaring secret requirements or grants are rejected after evaluation, before engine access, including public core load, plan and deploy APIs; they are not treated as ordinary stacks. Existing secret-history and unknown-source protections remain in place for ordinary command paths. Disabling these entrypoints does not remove containers, secret sources, or coordination state.

Ordinary stacks and ordinary operation/coordination interfaces remain available, subject to their existing guards. Do not use ordinary commands to bypass protections on formerly secret-enabled stacks. Previously created resources require an independently authorized recovery procedure; this change does not provide one.

Regular Docker integration CI independently provisions a trusted native target and exercises the still-active operation envelope, qualified coordination, named preflight, recovery, ownership and ordinary no-prune paths; regular Podman integration CI exercises the operation envelope and ordinary no-prune. These use existing synthetic fixture tests despite their historical names. Clients must handle unavailable discovery and failures rather than bypassing them.
