# Experimental read-only host agent (incomplete)

`dill-agent` implements `POST /v1/session`, bounded `POST /v1/inventory`, normalized `POST /v1/inspect`, bounded `POST /v1/logs`, and, only when explicitly configured with a Brine verification key, `POST /v1/reveal`. This is not yet a complete read agent. The existing `dill-serve` is unchanged and must not be forwarded in its place.

The binary listens only on a Unix socket in a pre-existing, owner-only directory and refuses to replace an existing path. It reads an owner-only Ed25519 seed file (64 hex characters), and explicitly connects to a configured Docker Unix socket without environment-based endpoint selection. Supply `--socket`, `--engine-socket`, `--engine-id` (enrolled lowercase UUID), `--daemon-id`, `--generation`, and `--key-file`. The daemon ID is rechecked through Docker `/info` for each session and authorized reveal. Treat the path, daemon ID, agent public-key fingerprint, engine UUID, generation, SSH host key and reveal verifier key as independently enrolled out of band. Docker daemon IDs are not cryptographic attestations, and sockets can proxy remotely. Podman is not supported by this CLI.

Inventory sorts full IDs and re-inspects each candidate's live ownership labels before exposing it. Cursors are authenticated, scoped to the process epoch and enrolled engine/generation, and expire after 60 seconds. An inventory over 1,000 engine containers fails instead of silently truncating; churn can cause duplicates or omissions across pages. The Docker list response itself is capped at 8 MiB and individual inspections at 2 MiB.

Inspect fetches a fresh full-ID Docker inspection, requires live ownership labels and returns a normalized allowlist. Only environment keys are returned; malformed or duplicate environment entries fail the request. Commands, mount paths and healthcheck arguments may still contain secrets. The profile has bounded strings and collections and excludes arbitrary labels.

Logs are streamed without persistence in NDJSON. Docker log drivers other than explicit `json-file` or `local` fail closed; streams are limited to two, a 1,000-line maximum requested tail, 1 MiB of decoded content, and 15 seconds for tail or five minutes for follow. A disconnected client cancels the engine stream. The agent periodically rechecks daemon identity and live ownership while streaming. Logs can contain secrets; do not cache or auto-resume them.

Reveal is opt-in with `--reveal-public-key` containing the enrolled Brine Ed25519 public key in hex. Only valid, current, per-container interactive `env.values` grants signed by that key are accepted. Nonces are consumed in memory before engine access, even if the response fails; an epoch generated on every start prevents reuse after restart. A clock rollback disables reveals until restart; a full nonce cache fails closed. Never clone or snapshot a running process: doing so invalidates the replay guarantee. A fresh inspect must return the exact full Docker ID and live Dill ownership labels. Environment values can contain secrets; callers must not persist, cache or log them. The signer asserts interaction; the agent cannot verify that a human actually confirmed it.

**Authorization boundary:** the agent does not authenticate callers. The epoch, request ID and signed session proof authenticate neither an HTTP client nor its authorization to read: anyone who can connect to the Unix socket can request inventory, inspect and logs. Reveal additionally requires a valid signed single-use grant. Restrict socket and parent directory permissions, ownership and ACLs, every path ancestor, and SSH account/stream-local forwarding permissions to authorized principals. The binary checks that the immediate parent is a non-symlink directory owned by its user with no group/other mode bits, and chmods the socket 0600; it does not validate ACLs, ancestor ownership/permissions, mount namespace, SSH configuration or filesystem races. Operators must secure and audit those independently before enabling the agent. The signing-key file and every ancestor of its path must likewise be trusted and protected against unauthorized reads, replacement and ACL grants; the file owner/mode-bit check does not verify ACLs, protect ancestors, or prevent path races. Provision and audit those controls out of band. SSH setup, enrollment, client proof verification and real SSH tests are not provided. No TCP listener is offered. Podman has not been qualified.

The reveal grant signing format is **`brine-agent-reveal/2` with mandatory request binding**, a breaking revision of the earlier request-unbound `/1` format. The grant JSON requires `requestId`, exactly the 32 lowercase hexadecimal characters of the 128-bit `X-Request-Id` header; the client chooses it before approval/signing and sends that exact value in both places. The agent validates the actual header independently and compares it with the signed field before nonce consumption or engine access; it never supplies or substitutes the field. The Ed25519 input is the ASCII domain `brine-agent-reveal/2` followed by NUL; then length-prefixed UTF-8 `agentId`, `engineId`; unsigned 64-bit big-endian `generation`; length-prefixed `epoch`, `containerId`, `sessionId`, `nonce`, `requestId`; unsigned 64-bit big-endian `issuedAt`, `expiresAt`; length-prefixed `scope`; and the single byte `01` for `interactive=true`. Each length prefix is an unsigned 32-bit big-endian byte count. Signature is canonical unpadded base64url. Old grants without `requestId` and old signatures are rejected, with no fallback. **Cross-app migration:** update the Brine signer/client and agent together; the signer must approve and sign the exact header ID in the position above. Earlier clients cannot reveal against this agent.

`internal/hostagent.IdentitySource`, `InventoryBackend`, `InspectBackend`, `LogsBackend`, and `RevealBackend` are narrow integration interfaces. The Docker implementation performs live ownership checks, bounded normalized reads and periodic stream identity checks. The reveal backend returns a fresh inspection for the exact full ID, including labels and environment from that same inspection. These protections do not authenticate callers or replace the socket and host controls above. Inspection and logs may contain secrets.
